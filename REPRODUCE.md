# Reproducing TA-DVFG

Run commands from the repository root. The three levels are deliberately
separated so reviewers can validate reported values without retraining models.

## Level 1: existing outputs, no experiment reruns

Purpose: verify provenance and regenerate derived tables/figures from existing
CSV/JSON evidence. No dataset, model training, topology sweep, or download is
required.

```bash
python scripts/verify_supplement_coverage.py
python scripts/verify_reported_values.py
python scripts/regenerate_artifacts.py
```

Expected outputs:

- `artifacts/regenerated/{hgb,k_sensitivity,movielens,mechanisms,nested_weak_scaling,alignment_acm_hard}/`
- `dist/aaai27_all_experiments_code/{MANIFEST.txt,SHA256SUMS.txt}`
- `dist/aaai27_all_experiments_code/TA-DVFG_AAAI27_All_Experiments_Code.zip`

The verification scripts compare the bundled evidence with fixed reported-value
checks. They do not rewrite any paper, raw CSV/JSON, cache, or protected figure.

## Level 2: lightweight deterministic validation

Purpose: validate algorithm invariants, synthetic MovieLens leakage boundaries,
bundled seed evidence, and package integrity without replay caches.

```bash
python -m pytest tests/unit tests/smoke -q
python -m pytest tests/test_experiment_plan.py tests/test_reviewer_defense.py -q
python -m compileall .
python scripts/verify_reported_values.py
python scripts/verify_package.py
```

The package includes historical provenance/mechanism implementations for code
inspection, plus their compact seed-level and statistical outputs. The commands
`analysis/provenance/run_testatbestval_replay.py`,
`analysis/provenance/run_topology_provenance.py`, and
`analysis/mechanisms/run_peer_exchange_audit.py` are **non-runnable
derived-evidence analyses in the clean ZIP** because their large NPZ replay
bundles are intentionally excluded. They must not be presented as Level-2
clean-ZIP commands.

## Level 3: full experiments (documented only)

Do not run these commands as part of repository cleanup or package validation.
They train local predictors and may require hours to days on CPU.

### HGB cached core

Prerequisites: PyTorch/PyG versions in `environment/`, ACM/DBLP/IMDB HGB data
under `data_hgb/`, adequate disk for trajectory caches, and roughly 16--32 GiB
RAM. The reported environment used CPU-only PyTorch.

```bash
python experiments/run_cached_core.py --datasets ACM,DBLP,IMDB --settings main,hard --seeds 42,43,44,45,46 --epochs 300
```

Expected outputs are per-setting seed/config/summary files below `results/` and
prediction caches in the configured cache directory. Commands generated by
`experiments/experiment_plan.py` are the authoritative defaults; direct engine
CLI defaults intentionally preserve older historical behavior.

### Nested weak-party scaling

Prerequisites: HGB ACM/DBLP data or existing 18-party caches. A full fresh run
trains ten 18-party cache trajectories before replaying nested subsets.

```bash
python experiments/run_nested_weak_scaling.py --datasets ACM,DBLP --seeds 42,43,44,45,46 --epochs 300
```

Expected raw/summary/paired-delta/figure/manifest outputs are written to the
runner's `--output-dir`; caches default to `results/nested_weak_cache/`.

### MovieLens

Prerequisite: the MovieLens 1M `ratings.dat`, `users.dat`, and `movies.dat` files
under `data/movielens/ml-1m/`. Network download is optional and not part of the
validated package workflow.

```bash
python experiments/movielens/run_movielens_tadvfg.py --data-dir data/movielens/ml-1m --output-dir outputs/movielens --seeds 42,43,44,45,46 --num-parties 5 --setting five --local-epochs 8
python experiments/movielens/run_movielens_tadvfg.py --data-dir data/movielens/ml-1m --output-dir outputs/movielens_main15 --seeds 42,43,44,45,46 --setting main --local-epochs 8
python experiments/movielens/run_movielens_tadvfg.py --data-dir data/movielens/ml-1m --output-dir outputs/movielens_hard15 --seeds 42,43,44,45,46 --setting hard --local-epochs 8
```

Expected outputs include party-performance, per-seed, summary and topology JSON
files in each output directory. All preprocessing and fitted statistics are
computed from training rows only.

### Latent-alignment reference

Prerequisites: ACM HGB data and enough disk for five fresh hidden-state caches.
This suite must remain separate from historical cached-core results.

```bash
python experiments/alignment_references.py --dataset ACM --setting hard --seeds 42,43,44,45,46
```

Expected outputs include hidden-export equivalence, per-seed/summary/statistics,
communication/parameter counts, train curves and failed diagnostic variants.

## Integrity rules

- Never select topology or epochs using test labels.
- Never compare alignment caches as if they were historical HGB cached-core runs.
- Never treat the historical `selected_edges` field as best-validation topology
  identity; use replayed best-validation state.
- Never overwrite `paper/source/` or historical raw/cached outputs during
  reproduction. Generate into `artifacts/` or a new output directory.
